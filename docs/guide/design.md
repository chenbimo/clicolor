# 设计与语义

## 一个类型,一套机制

对外公开面只有四样东西:

1. `Style` 值类型:不可变,链式方法与常量并存
2. 公开常量:前景十六、背景十六、修饰五项、预设五个、起步兜底 `default`
3. 两个带参方法:`hex(c)` / `bg_hex(c)` 与收尾 `text(文本)`
4. 一对开关:`set_enabled` / `is_enabled`,外加 `hyperlink`

没有第二个等价入口。不提供数组拼样式 `wrap_ansi([Ansi, Ansi], ...)`,不提供字符串拼样式名 `style("red bold")`。前者是旧版 `Ansi` 枚举时代的形态,本次重构被语义清楚、顺序更稳的值链取代;后者把类型安全换回字符串,不值得。

## SGR 对照

本库的全部输出由三类字节构成:

| 语义      | SGR 序列            | 说明                |
| --------- | ------------------- | ------------------- |
| 前景 8 色 | 30 到 37            | black 到 white      |
| 前景亮 8 色 | 90 到 97          | bright_* 系列       |
| 背景 16 色 | 40 到 47、100 到 107 | bg_* 系列,同上规则 |
| bold      | 1                   |                     |
| italic    | 3                   |                     |
| underline | 4                   |                     |
| inverse   | 7                   |                     |
| strikethrough | 9               |                     |
| 真彩前景  | 38;2;r;g;b          |                     |
| 真彩背景  | 48;2;r;g;b          |                     |
| 重置全部  | 0                   | 每段收尾必发         |

序列不合并成一个 `ESC[1;4m`:每项独立 `ESC[..m`,由收尾 RESET 结束。合并能省字节,读起来难;语义粒度更利于测试断言,选择拆开。

## 位掩码表示

一个 `Style` 内部只写四个字段:

- `fg` 与 `bg`:各自一个 Int,0 到 15 表示色号,`-1` 表示没设,`-2` 表示置成真彩看 hex 字符串
- `attrs`:五个修饰的位掩码,1 bold、2 italic、4 underline、8 inverse、16 strikethrough
- `hex_fg` / `hex_bg`:真彩色的原始字符串,渲染时才解析

这套表示让聚合零字符串分配。链上每步只是把这几个 Int 拷一份,真彩色字符串只在内存里引用。没有动态解析,也没有每步重新生成对象。成本比旧版「枚举 + 数组」更低:数组是堆对象,常量起步到收尾之间的每一步都要新建一次;位掩码链只是在栈上拷几个 Int。

## 发射顺序 = 书写顺序

`text()` 按前景、背景、修饰的次序写字节,与书写约定一致。SGR 参数的顺序在终端语义上无感,所以把「书写序」「字节序」「阅读序」三者合一,降低一切对齐成本,也保证测试能直接按字节断言整段输出。

## 空样式与降级

三个降级点,全部保证「坏值不致中断」:

- 空 Style 直接返回原文,一个字节都不写
- 开关关闭时同样原样返回
- hex 非法时转 `(0,0,0)`,任意坏值都走「渲染成黑」这条窄路径

hex 解析规则:合法字符收集,非法跳过,三位允许扩展到六位(每位 × 17),满六位两两拼字节;其他长度一律按 `(0,0,0)`。

## 开关是显式的

不自动探测 TTY 和 `NO_COLOR`,理由:

- 纯函数库,读写全局环境是对三 target(js / wasm-gc / native)不一致的源头
- chalk 的「悄悄关色」是便利,也是排查颜色问题时的迷宫,把同一件事交给调用方更透明
- `set_enabled(false)` 一次,之后所有 `text` 合同都改为「原样返回」,无路径分叉

`set_enabled` 返回旧值,就是为了上层能恢复原状态。

## 与 clitable 的分工

本包只管转义序列的生成与收尾:什么字该染色、染色宽度、断行后序列是否还开着,全部归下层引用它的库。宽度剥离库存 `strip_ansi` 不收进来,避免两个包互相依赖。

具体到 clitable:列宽计算用「显示列数」,ANSI 序列计 0 列,OSC 8 也零宽。这些能力在宽度层独立存在,clicolor 对此零知识。

## 生态出处

这份能力都有原型,取舍如下:

| 来源              | 吸收的                                          | 没吸收的                        |
| ----------------- | ----------------------------------------------- | ------------------------------- |
| chalk (npm)       | 链式不可变设计、预设常量、`NO_COLOR` 由上层判断  | 模板字符串嵌套、TTY 自动探测    |
| picocolors (npm)  | 单样式一步直达                                  | 类型工艺、嵌套                   |
| lipgloss (Go)     | 不可变 Style 值、包级常量                        | 布局 Padding / Width、颜色降级   |
| termenv (Go)      | 设想中的组合层思路                               | Profile 自动降色                |

排除项的统一理由:**没有桌面终端的真实需求就引入机制,是提前抽象**。等到这些需求到来,再开第二版。

## 边界(当前明确不做)

- 嵌套样式(富文本树,内层关闭时重开外层),设计稿是独立 `Rich` 组合层,`seg` 与 `rich` 两种节点即可表达,等 clitable 出现带色单元格截断需求时启动
- 256 色降级:桌面与管道普遍支持 24 bit,主动降色是以运算换边缘场景的兼容,先不做
- TTY 自动探测:理由见开关一节

## 测试与验收

测试在 `src/ansi_test.mbt`,每个公开行为都有字节级断言:

- SGR 序列逐字节对应
- 常量与方法链同构,顺序无关性对拍
- 真彩、坏值、空串、开关、复用、链接各有独立测试名

改序列行为必须同步改对应测试名,测试名就是覆盖索引。
